# 個人翻譯網站 — 專案討論摘要

## 專案概念

青空文庫/古騰堡計畫翻譯協作站,以 GitHub 為核心基礎設施,零維運成本、盡可能開放授權,重視內容的長期保存價值。

**專案名稱**:信標文庫,網域註冊為 `beaconarchive.org`(**已定案**,2026-08-16)。全站分頁標題結尾、header 標題、footer、`/about/` 頁面已統一改用這個名稱,見 `scripts/app/layout.js` 的 `SITE_NAME` 常數。

- **核心原則**:不自建後端、不自建資料庫、全部借用外部服務的免費機制
- **協作模式**:譯者開 PR 提交,通過自動檢查即合併上線,目前規模小、無額外人工審核(細節與理由見 [翻譯者指南.md](./翻譯者指南.md#8-自動檢查)、[架構規格.md 第 6 節](./架構規格.md#6-驗證規則build-time--ci))
- **翻譯者誘因**:無金錢報酬,靠瀏覽次數/喜歡數紀錄、個人 profile 頁面

## 技術組合

| 項目 | 方案 |

### 可以沒有，但有了不錯
- [ ] 不用改程式，透過MD檔案，更新基礎頁面資訊：渲染基礎頁面會讀取對應.md檔案，像是：首頁的公告


- [ ] GitHub API 分析貢獻量：無關於有沒有使用者的客觀指標，只要活動就會累積，可以當成翻譯者成就來源。
- [ ] 譯文頁面嵌入threads貼文：當成表達喜歡和討論的區域。會有第三方追蹤問題，JS會變重。不確定有沒有需求。
- [ ] 內建討論區：Cloudflare D1(確保討論也是本站持有)。可以自己擁有討論資訊，但必須依賴外部環境，而且也不見得有人用。

- [ ] 翻譯提交工具：給url，自動爬蟲建立contents內的檔案，會處理重複問題，使用者只要填入翻譯和額外資訊(像是：wikidata連結)，讓發布流程像在普通網站發文，不用碰GIT(GitHub 帳號登入串接)
- [ ] 網站本身提供翻譯提交工具：除了同源政策沒辦法爬蟲，其他大部分功能都可以辦到
- [ ] Desktop APP翻譯提交工具：都可以做辦到，但schema同步麻煩
- [x] cli翻譯提交工具：都可以辦到，但技術門檻高

- [ ] 介面多語系：根據目標翻譯者/使用者社群，可能不需要
- [ ] 全文搜索：用Pagefind靜態索引，結合目前的結構JSON索引檔案並行，這個負責內文，比如想找台詞，想找某句話，想找角色。但這通常適合找原文內容，而不是翻譯內容，所以效果不大。

# 信標文庫（`beaconarchive.org`）


## 專案概念
非營利且無廣告的公領域書籍（青空文庫、古騰堡計畫）翻譯分享平台。翻譯者透過 GitHub 無償提交譯文，所有作品皆採用 CC BY-SA 4.0 開放授權。人人皆可免費閱讀、轉載、改作與商用（需標註原譯者）。

避免官僚化漫長審查。審查只審置入內容、惡意破壞、排版錯漏字，翻譯品質和風格交由使用者判別。

翻譯者沒有金錢報酬，只有貢獻紀錄(字數、作品數)、使用者瀏覽次數，個人檔案頁面的自我介紹。

以 GitHub + CloudeFalre 為核心基礎設施，零維運成本。不自建後端、不自建資料庫、全部借用外部服務的免費機制。

## 技術組合

| 項目 | 方案 |
|---|---|
| 內容儲存/協作 | GitHub repo(PR 提交 → 自動檢查 → 合併上線,目前無額外人工審核) |
| 網站託管 | Cloudflare Workers |
| 建置流程 | 純 Node.js build script |

## 考慮實作功能

### 網站維護
- [ ] 不用改程式，透過MD檔案，更新基礎頁面資訊：渲染基礎頁面會讀取對應.md檔案，像是：首頁的公告

### 翻譯者成就
- [ ] GitHub API 分析貢獻量：無關於有沒有使用者的客觀指標，只要活動就會累積，可以當成翻譯者成就來源。
- [ ] 譯文頁面嵌入threads貼文：當成表達喜歡和討論的區域。會有第三方追蹤問題，JS會變重。不確定有沒有需求。
- [ ] 內建討論區：Cloudflare D1(確保討論也是本站持有)。可以自己擁有討論資訊，但必須依賴外部環境，而且也不見得有人用。

### 翻譯者生產力
- [ ] 翻譯提交工具：給url，自動爬蟲建立contents內的檔案，會處理重複問題，使用者只要填入翻譯和額外資訊(像是：wikidata連結)，讓發布流程像在普通網站發文，不用碰GIT(GitHub 帳號登入串接)
- [ ] Gooogle Form翻譯提交工具：使用者提交表單，在google sheet新增一列資料，自己跑翻譯cli
- [ ] Gooogle Form翻譯提交工具(自動化)：google app script把sheet的翻譯資料傳給github repo，github ci執行翻譯cli，分支提交PR合併。
- [ ] 上述自動化流程的失敗通知：CI 執行失敗時，提交表單的人完全不會知道。可以用 Apps Script 內建 `MailApp` 寄信通知（免費帳號額度 100 封/天，夠用），不用另外找服務。
- [ ] 上述自動化流程的修正機制：投稿後想修正（錯字等）不該重用新投稿表單——來源網址稍有出入，查重邏輯可能誤判成別的作品，或生出重複資料。應該另開一個用 uuid 定位的修正流程，只允許改譯文自己的欄位（標題/摘要/正文），不開放改 work_id/edition_url/uuid 這些定義身分的欄位，可沿用同一套 repository_dispatch→Actions→auto-merge，換一支更簡單、不用爬蟲查重的腳本。
- [ ] (暫時凍結)網站本身提供翻譯提交工具：除了同源政策沒辦法爬蟲，其他大部分功能都可以辦到
- [ ] (暫時凍結)Desktop APP翻譯提交工具：都可以做辦到，但schema同步麻煩
- [x] cli翻譯提交工具：都可以辦到，但技術門檻高

### 使用者便利性
- [ ] 翻譯閱讀畫面客製化閱讀設定：文字大小、行距、主題(深色/米黃/白色)
- [ ] 翻譯閱讀畫面分頁提供正文：點一下換頁的體驗，對電子書閱讀器，或單純習慣這種閱讀方式的人讀起來比較順暢。
- [ ] 翻譯閱讀畫面客製化渲染：現在純粹用`markdown-it`轉換md，無法控制排版。透過解讀token，自己重繪html可以實現各種設計。像是客製化註解樣式。

- [ ] 介面多語系：根據目標翻譯者/使用者社群，可能不需要
- [ ] 全文搜索：用Pagefind靜態索引，結合目前的結構JSON索引檔案並行，這個負責內文，比如想找台詞，想找某句話，想找角色。但這通常適合找原文內容，而不是翻譯內容，所以效果不大。
